  - Lỗi mạng hoặc lỗi máy chủ API (`REQUEST_FAILED`, `HTTP_4xx/5xx`, `HTTP_402_REFUSED`) không còn làm tăng bộ đếm vòng lặp (nhưng vẫn tính vào giới hạn tần suất gọi mỗi phút); chỉ lượt bị Rule Engine hoặc smart contract chặn mới tính vòng lặp.

## Quyết định
- **Phân tách `recordFailure` (rule-engine/contract) và `recordAttempt` (network/HTTP) theo `blockedBy` của `formatErrorOutcome`:** giúp giữ nguyên giới hạn tần suất `maxRequestsPerMinute` khi API hoặc RPC chập chờn mà không khóa nhầm `LOOP_DETECTED`.
- **Giữ `toRejections` trả `Rejection[]` và tách `toRejectionsWithTotal` cho API/test mới:** tránh phá vỡ các đoạn gọi hoặc test cũ kỳ vọng mảng `Rejection[]`, đồng thời `useRejections` vẫn fallback về `body.items.length` nếu nhận payload không có `total`.
- **Tắt retry ngầm ở mức per-request (`{ retries: { strategy: "none" } }`) trong `@google/genai`:** vì trong SDK v3.3.0 lớp `GeminiNextGenInteractions` không tự kế thừa `httpOptions.retryOptions` từ constructor cho `retry_config`, nên truyền qua `options` của `interactions.create` mới chặn triệt để retry ngầm 429; kết hợp giữ `lastError` ở `createInteractionWithRetry` phòng trường hợp retry lớp ngoài bị timeout.
- **Không cài `@emotion/is-prop-valid` vào `web/package.json` (`ISSUE-09`):** theo lựa chọn của Nguyên nhằm giữ sạch dependency trước freeze; dùng `npm --prefix web run build && npm --prefix web run start` khi quay video để bản production không hiện cảnh báo `isActive` của Privy.
