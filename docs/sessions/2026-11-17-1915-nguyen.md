# Hoàn thành chỉ tiêu kỹ thuật 17/11: nút 1-click "Chuyển thành API quen" và MCP Server cho Bên A

## Mục tiêu phiên
Triển khai trọn vẹn 2 đầu việc ngày T3 17/11 trong `docs/DEADLINE_BEN_A_B.md` trên nhánh mới `feat/17-11-ben-a-b-mcp-whitelist` mà không đụng `contracts/` và không làm vỡ luồng demo 7 bước.

## Đã làm
- **Nút 1-click "Chuyển thành API quen" trên Dashboard (`web/`):**
  - Ngay cạnh các giao dịch API lạ / nhóm Sandbox ở ô `[2] Dòng tiền` và các lần bị chặn liên quan tới địa chỉ lạ / Sandbox ở ô `[4] Bị từ chối`, Dashboard giờ hiển thị nút **Chuyển thành API quen**.
  - Nút chỉ hiện khi địa chỉ nhận tiền (`to`) chưa có trong whitelist hiện tại của policy đang xem; khi đã được whitelist, nút tự ẩn (hiển thị nhãn xác nhận `Đã thành API quen ✓`); khi ví chủ Privy chưa sẵn sàng, không phải chủ policy hoặc đang có giao dịch khác chờ xác nhận thì nút bị khóa kèm lý do rõ ràng.
  - Bấm nút sẽ kích hoạt đúng luồng ký Privy (`setWhitelist(targetAddress, true)`), hiển thị trạng thái `Đang ký` → `Đang chờ xác nhận` (kèm link Snowscan) → `Xong`, và tự động làm mới trạng thái policy + whitelist + dòng tiền sau khi xác nhận trên Fuji.
- **MCP Server mỏng cho Bên A (`agent/src/mcp.ts`):**
  - Cài `@modelcontextprotocol/sdk` (truyền stdio) và `zod`, thêm script `"mcp": "node --env-file=../.env src/mcp.ts"` trong `agent/package.json`.
  - Cung cấp 3 tool cho Antigravity / Claude Code: `test_unknown_api` (thử API lạ theo URL hoặc `payTo` qua lớp bảo vệ URL/SSRF + tần suất/trùng lặp + Sandbox on-chain, trả dữ liệu nếu lọt ngưỡng hoặc lý do bị chặn tiếng Việt và ghi `agent/logs/audit.json` cho Dashboard đọc), `call_trusted_api` (gọi API trong danh mục Trusted hoặc API đã được chủ ví bấm **Chuyển thành API quen** trên Dashboard, trả dữ liệu kèm link Snowscan), và `get_policy_status`.
  - Cập nhật hướng dẫn chạy & cấu hình MCP vào `README.md`.
- **Kiểm thử tự động:**
  - `agent/`: `5/5` file, `24/24` unit test Vitest pass (gồm 6 test offline mới cho `mcp.ts` qua `InMemoryTransport`), `npm run typecheck` pass, smoke test JSON-RPC `initialize` qua stdio trả phản hồi sạch trên `stdout`.
  - `web/`: `9/9` file, `71/71` unit test Vitest pass (gồm 6 test mới cho `whitelistPromote.ts`), `npx tsc --noEmit` pass, `npm run lint` pass, `npm run build` hoàn tất.

## Quyết định
- **Tái sử dụng `executeSetWhitelist` + `useOwnerTx` thay vì viết luồng ký riêng ở `ActivityCards.tsx`** — giúp nút 1-click dùng chung mô phỏng trước (`simulateContract`), xử lý lỗi tiếng Việt và `TxBanner` ở đầu trang, đồng thời tránh trùng lặp code với `SetupCard`.
- **Mở rộng `useWhitelist` đọc thêm các địa chỉ từ `spends` và `rejections`** — vì trước đây `useWhitelist` chỉ đọc 2 seller cố định; nếu không đọc địa chỉ lạ thì sau khi bấm `setWhitelist(0x1111…, true)`, UI sẽ không tự nhận ra địa chỉ đó đã vào whitelist để ẩn nút.
- **Chuyển `console.log`/`console.info` sang `stderr` trong `main()` của `agent/src/mcp.ts`** — vì `policySigner.ts` ghi log bằng `console.log`, nếu để lọt ra `stdout` sẽ làm hỏng khung JSON-RPC của `StdioServerTransport` (trong khi giữ nguyên hành vi CLI `run.ts`).
