# Hoàn thành GĐ 0: Spike kiểm chứng x402 qua ERC-1271 trên Avalanche Fuji

## Mục tiêu phiên
Đồng bộ 4 quyết định đã chốt vào SPEC/ROADMAP và thực hiện Spike GĐ 0 để chứng minh luồng x402 với người trả là smart contract theo ERC-1271 trên Fuji. Mục tiêu đã hoàn thành 100%.

## Đã làm
- Cập nhật 4 quyết định lớn vào `SPEC.md` và `ROADMAP.md`: hạn mức phân tầng (Trusted/Sandbox), chu kỳ demo 30s + `release(nonce)` ở GĐ 1, LLM Gemini `gemini-3.8-flash` + 2 API mock có cấu trúc, stack web Privy + viem thuần (bỏ wagmi).
- Viết và test contract tối giản `SpikePolicy.sol` hỗ trợ ERC-1271 (`isValidSignature` trả `0x1626ba7e` khi digest đã duyệt).
- Viết script `DeploySpike.s.sol`, deploy lên Fuji tại `0x38706AFC0f92b6908389ebF377aab688a2BDe951` và nạp 0.01 USDC.
- Viết custom `policySigner.ts` dùng viem: nhận EIP-712 typed data, gọi `SpikePolicy.approve(digest)` on-chain bằng ví agent, trả chữ ký `0x`.
- Dựng API seller thời tiết từ starter kit BTC và kiểm thử trọn vòng x402 qua 3 facilitator:
  + Facilitator tự host (`localhost:4022`): Thành công 200 OK, tx `0x52e1d691...74ba` (xem SPIKE.md).
  + PayAI Network (`facilitator.payai.network`): Thành công 200 OK, tx `0xfb25dd4e...6bf3` (xem SPIKE.md).
  + Ultravioleta DAO (`facilitator.ultravioletadao.xyz`): Bị từ chối 402 với lỗi `invalid_signature`.
- Viết báo cáo chi tiết tại `docs/SPIKE.md` và chính thức chốt mục "Chưa chốt #1" trong `SPEC.md`.

## Quyết định
- Chốt dùng Facilitator tự host làm mặc định khi demo (ổn định, không phụ thuộc bên ngoài) và PayAI làm dự phòng công khai. Loại bỏ Ultravioleta DAO vì không hỗ trợ ERC-1271.
- Chốt dùng hạn mức phân tầng (Trusted vs Sandbox) thay vì whitelist cứng.
- Chốt demo period 30s (`DEMO_PERIOD_SECONDS=30`), chuyển `release(nonce)` vào GĐ 1.
- Chốt Gemini `gemini-3.8-flash` cho agent và Privy + viem thuần cho web.
